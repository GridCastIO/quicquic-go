## Purpose and authority

This document is the single collection contract that Q2 executes on its exact activation candidate. It binds the merged readiness apparatus (E1–E3, P1–P2, C1–C4) to candidate rules, commands, venue, toolchains, build cells, release applicability, inventory, criteria, attribution and continuing coverage. It records evidence that is missing as a blocker, never as a waived row.

Q1 ran nothing native. It ran no fixture, sampler, build of a test binary, peer or measurement, installed nothing, and reserved no venue. Every fact below comes from reading source, the merged readiness receipts, hosted job metadata and read-only host identity commands.

The protocol becomes executable only when the [owner decision receipt](#owner-decision-receipt) records approval of every row in the [decision table](#decision-table) together with this document's exact revision. A partial approval is not executable. Neither a runner, a readiness label nor this document grants execution authority. The owner, or a maintainer the owner names, owns venue access, privileged sampling, the operational inventory and any support exception.

A protocol change after approval needs the owner's reapproval before any affected step runs. That includes a command, cell, inventory count, criterion, timeout or follow-up method.

## Candidate and identity rules

1. **Candidate.** One clean commit on Q2's feature branch that contains the activation change and its acceptance-expecting tests. Every native step runs at that commit with `git status --porcelain` empty. Each record carries the commit and its tree (`git rev-parse HEAD` and `git rev-parse 'HEAD^{tree}'`).
2. **Binaries.** Every test binary, peer and relay is built from the candidate inside this protocol's steps, in a fresh directory, and is never reused from an earlier candidate. D4 selects how a receipt proves the binary came from the candidate.
3. **Freshness.** Any change to the candidate's tree after collection begins invalidates all collected native evidence, except a change whose exact diff is reviewed and recorded as prose or support metadata that no selected build, fixture, test or receipt check reads. Build inputs include assembly such as `send_thread_qos_darwin_arm64.s`, headers and embedded files, and `TestMultipathSupportMatchesEvidence` reads JSON under `docs/audits`, so neither category is exempt by path. If `main` gains non-documentation changes before Q2 merges, Q2 stops and asks the owner either to re-collect or to accept an exact applicability disposition for that diff. Evidence is never silently carried to a different tree.
4. **Host identity per run block.** `sw_vers`, `uname -a`, `sysctl -n hw.model machdep.cpu.brand_string hw.perflevel0.physicalcpu hw.perflevel1.physicalcpu`. Per toolchain: `go version`, `go env GOROOT`, and the sha256 of `$GOROOT/bin/go`, `$GOROOT/src/internal/poll/fd_unix.go` and `$GOROOT/src/internal/poll/fd_poll_runtime.go`. The poller sources bind each EAGAIN and deadline observation to the exact installed toolchain source.
5. **Retention.** Every attempt, including failed, contaminated and interrupted attempts, keeps its raw output, `go test -json` stream, peer logs, build identity and driver records under one results root for the candidate.

**Attempts and ledger.** `$N` is the observation number (1–3) that pairs a round; `$A` is the attempt number under it, starting at 1. The drivers refuse an existing output directory, so a replacement runs at `a2` under the same `$N` and the original stays in place. The receipt names the accepted attempt for each `$N`, and only that attempt enters the round's comparison. `ordinary_cost.py` charges one instance per X11 arm or X12 attempt, with its `occupied_s` as host seconds, and keeps the charge on failure. Before a full X11 pair it requires headroom for two instances and 2 × 135 s; before X12, one instance and 135 s. The D9 inventory is 52 cost instances (26 pairs, two instances each), 2 lifecycle attempts and 37 topology runs, at 135 s each. The D10 replacement allowance adds at most 4 cost instances (2 pairs) and 2 topology runs. The first X11 invocation therefore passes `--remaining-instances 56 --remaining-host-seconds 7560` (56 × 135 s), the first X12 invocation `--remaining-instances 2 --remaining-host-seconds 270`. Each later invocation passes the previous balance minus that invocation's `instances_charged` and `host_seconds_charged` from its `ledger.json`, including an invocation that failed after one arm. Topology runs, one per X13 invocation, are counted in the protocol's own receipt. Exhausting the inventory or the allowance stops collection for the owner's decision.

### First write-wait observation

X2 is the first native step after identity, and it runs on T27 before anything else, so that the riskiest native trigger is known early.

- **Fixture owner:** the transport test suite, for E2's `TestNativeDarwinBlockedWriter` (`native_darwin_writer_test.go`, `//go:build darwin`, traversal cases under `nativequal`) and its `native_darwin.py` profile.
- **Receipt fields:** every traversal case has `evidence`, `send_buffer`, `control_bytes`, `payload_bytes`, `positive_control`, `poller_witness`, `injected`, `traced`, `result`, `uncertain` and `native_return_after_deadline_ms`. The two recorder cases, `eagain-to-deadline` and `queued-expiry`, add `native_calls`, `deadline_preserved`, `deadline_reset` and `native_returned`. Case-specific facts: `publication_ms` and successor facts for `eagain-to-deadline`; the queued facts below for `queued-expiry`; and the close, cancel, join and caller-write facts with `close_to_join_ms` for `active-close-join`. The run carries the build identity, binary sha256 and native identity.
- **Missing trigger:** a traversal case with any class other than `native-traversal` (`no-witness`, `expired-before-dispatch`, `stale-deadline`, `missing-native-return`, `reset-failure` or `simulated`) stops Q2 collection. Trigger diagnosis and any repair go to E2's fixture owner as a separately scoped follow-up. A changed trigger, command or case set needs the owner's reapproval of this protocol before X2 runs again. A missing witness never counts as safe native deadline behavior, and activation stays blocked.

### Sampler capture and contiguity check

This runs only if D6 selects the sampler, under the privilege D6 authorizes. It comes before any record that uses `--host-sampler`.

1. Capture: exactly `/usr/bin/powermetrics --format plist --samplers cpu_power -i 1000 -n 60`, writing to standard output, under the privilege D6 authorizes. A small capture reader timestamps each NUL-terminated record's arrival on the monotonic clock and also records the clock just before launch and just after reaping.
2. The merged adapter must accept the whole capture: every record, including the first, has `is_delta` true, a positive integer `elapsed_ns`, cluster names labeled `E` or `P`, `idle_ratio` and `down_ratio`, with no repeated cluster name. A producer shape the adapter rejects (for example an absolute first record) fails X3 and goes to the #1552 follow-up.
3. The bounded capture must exit successfully with its 60 records; a capture with fewer than two complete deltas is `inconclusive` and fails X3. Contiguity is judged over the sampled interval, from the first record's arrival to the last. It passes only if the adapter accepted the capture; each consecutive arrival gap is within 50 ms of the later record's `elapsed_ns`; and the sum of `elapsed_ns` over the records after the first is within 100 ms of the time from the first arrival to the last. The time from launch to the first arrival is recorded, not judged, so an unknown startup delay alone cannot reject contiguous deltas. The adapter's own lifetime check (`SAMPLER_SLACK_S`, 50 ms) and its workload-window check stay independent of this test. Otherwise the adapter must classify gaps as `inconclusive` (a follow-up under [#1552](https://github.com/GridCastIO/quicquic-go/issues/1552)) before any `observed` record counts.
4. Before any captured bytes are committed as a fixture, check that they carry no host identifier beyond the model and OS fields the fixture already holds.

## Comparison criteria

### Deadline and timing criteria

The endpoint tolerance is the existing `endpointTolerance` of 20 ms (`native_endpoint.go`), unchanged. E2's records are untraced (`traced: false`), so, as for E6's uninstrumented classes, their timing is compared with it.

| Fact | Basis | Criterion |
| --- | --- | --- |
| `native_return_after_deadline_ms` (each traversal case) | Native return after the request's absolute deadline | At most 20 ms |
| `queued_expiry_ms` (`queued-expiry`) | From the queued deadline to the endpoint's terminal decision, the queued member's `returnedAt`. This is the corrected basis from [PR #1566](https://github.com/GridCastIO/quicquic-go/pull/1566); the case already refuses a decision before the deadline or after the observation. | At most 20 ms |
| `queued_publication_ms` (`queued-expiry`) | From the queued member's endpoint decision (`returnedAt`) to the fixture's observation of the result | Recorded, not judged. Never added to expiry. |
| `publication_ms` (`eagain-to-deadline`) | From the recorder's timestamp of the native `WriteMsgUDPAddrPort` return to the fixture's observation of the result | Recorded, not judged. |
| `close_to_join_ms` | From `Transport.Close` to the join | Recorded, not judged. The case's ordering facts (join after native return) are the requirement. |

A miss is a timing failure. It blocks activation and goes to diagnosis. It is not rerun until it passes, and the tolerance is not relaxed.

### Cost, lifecycle and topology criteria

These are the [accepted product thresholds](2026-10-24-multipath-reno-plan.md#accepted-product-thresholds), unchanged. No Linux exception, including the [R18](2026-10-24-multipath-reno-plan.md#r18--measure-ordinary-peer-costs-on-granted-endpoints) CPU dispositions, the [B9 support record](../audits/2026-11-15-bbr-b9-support.md) and the [B11 receipt](../audits/2026-11-15-bbr-b11/README.md), transfers to Darwin.

- **Verdict inputs.** For each judged X11 controller and cell, the inputs are the two validated arm records in `diagnostic.jsonl` of the accepted attempt (`$N/a$A`) for each of the three rounds. They carry the useful bytes, CPU, latency, flow series, close and error and RSS facts that `judge_cell` reads. `summary.json` also embeds the arm records under `attempts`; the JSONL pairs are the one named input, so the two never need reconciling. Each X13 ratio reads the verified topology summary of each accepted run. Both D12 options use these inputs.
- **Ordinary cost, Reno.** R18's `judge_cell` arithmetic, unchanged. Each of the three rounds pairs its unregistered and opted-in observations. Medians across rounds of four per-round values must pass: the `ordinary` flow's useful bytes, opted-in over unregistered, at least 0.95; server window CPU divided by all receiver useful bytes, opted-in over unregistered, at most 1.10; and the p99 control echo and p99 application send-call margins, each against the larger of 110% of baseline and baseline + 1 ms, not above zero. Any single round fails the cell if its opted-in observation has a timeout-only close, a write error or non-timeout close, an empty second in any flow's series (fair progress), or unbounded memory. Unbounded memory is R18's operationalization (`MEMORY_GROWTH_CEILING`): the server's peak RSS at the end above 110% of its peak RSS at the sample point (`peak_rss_end` against `peak_rss_at_sample` on Darwin, in normalized bytes). A miss blocks activation unless the owner gives an exact-result disposition for that cell.
- **Ordinary cost, BBR.** Reported with the same ratios but `judged: false`, as the existing convention does for newly matched BBR pairs (only the historical Linux BBR `stateless-pressure` diagnostic keeps a verdict there). The owner gives BBR primary/backup and aggregate their own ordinary-cost disposition on the exact results before activation.
- **Opt-out fallback pairs (O27).** Functional: both arms valid with useful delivery and no workload failure. Not judged.
- **Lifecycle memory.** Reported per phase: `go_heap_live`, `peak_rss`, detachment and grant joins, for Reno and BBR at `retired` state `closed`. No new threshold. The memory requirement is the bounded-memory criterion above, together with the owner's review of these phase records.
- **Topology, BBR aggregate.** [B11](../audits/2026-11-15-bbr-b11/README.md)'s arithmetic: medians of round-paired ratios, never ratios of unrelated medians. Observations pair by their number N (1–3) within a topology. On `disjoint`, the better single arm is chosen once, before any ratio, as the one of `single-a` and `single-b` with the higher median focal `useful_bytes`, and `single-a` when the medians are equal (B11's `>=`). On `disjoint`, the gates are the median of `aggregate` ÷ better-single `useful_bytes`, at least 1.20, and the median of `aggregate` ÷ `pair` `useful_bytes`, at least 0.95. On `shared`, the gate is the median of `competitor_stream_bytes` beside `aggregate` ÷ beside `pair`, at least 0.90. STREAM completion and DATAGRAM useful delivery are reported separately. `unequal` and the Reno primary/backup runs are reported, not judged. A failed judged cell blocks the aggregate support claim. It does not trigger more experiments.

Every native summary today carries no verdict (`judged: false`, `NATIVE_NOT_JUDGED`), so D12 decides how Q2 computes these verdicts.

## Attribution and contamination

- An observation invocation is **contaminated** when the host gate matches immediately after it, or when its sampler record is `inconclusive` after X3 passed. It is kept, never discarded, and is not counted as a product failure. Only a cost pair (X11) or a topology run (X13) gets one clean replacement, at the next attempt number under the same observation number, drawn from the D10 allowance. Every other invocation has no replacement capacity: a contaminated `native_darwin.py` profile run (X2, X4 or X6, which runs its whole profile with no single-case selector) or X12 lifecycle attempt is recorded as contaminated, and the owner decides before Q2 relies on it. Correctness rows X5 and X7–X10 are not timing-judged, so contamination there is recorded only.
- Under D6 A, a sampler that returns `unavailable` during X11 (launch failure, early exit or lost privilege) keeps the workload record and the sampler's status and reason. That observation is unattributed. It is replaced once from the allowance after the sampler is repaired, or the owner decides to accept it unattributed.
- Activity on efficiency cores is background activity, not contamination. `host_activity` exists only on X11 workload records. If the sampler is selected, their performance-cluster and efficiency-cluster activity are reported separately and not judged. X13 has no sampler: its host gate flags campaign overlap, and a clear gate leaves the cause of a topology miss undetermined.
- If the sampler is not selected, `host_activity` is `unavailable` in every X11 record. A cost miss is then not attributable from the record. It still blocks unless the owner disposes it.
- A load average alone never marks a run contaminated. Linux foreign-CPU arithmetic and its thresholds do not apply.

## Attempts and failure handling

- Each declared instance runs once. Per-invocation timeouts are as stated in each step and in the existing drivers: the matrix role context and C adapter at 30 s, the Go test at 90 s, the runner at 120 s, build and setup at 1200 s, and `native_darwin.py` cases at 60 s.
- A failed attempt stops its step and keeps its evidence. Diagnose before deciding anything. A replacement is legitimate only for a demonstrated external failure or contamination, and only within the D10 allowance; anywhere else it is the owner's decision. Never repeat until passing.
- A product failure returns Q2 to implementation and leaves activation unmerged. A fixture failure goes to that fixture's owner as a scoped follow-up, with protocol reapproval where its inputs change.

## Known limitations

- **Ordinary-demo stdio ([#1531](https://github.com/GridCastIO/quicquic-go/issues/1531)).** On Darwin a canceled `picoquicdemo` can lose its buffered output tail. Readiness is a bounded successful Dial and both exit statuses are checked. A missing log tail is never evidence for or against anything.
- **Darwin tuple gate ([#1530](https://github.com/GridCastIO/quicquic-go/issues/1530)).** All Darwin tuples are `127.0.0.1` with distinct ports. The abandon/reopen gate matches the exact armed address and port but cannot separate tuples by address. With quic-go-fast as server, the independent client reopens from the tuple path one used before (`addresses[1]`), as on Linux; the scenario is defined by a new wire ID. A changed tuple is exercised by `same-id-migration-rebinding`.
- **Family evidence seam.** X4 reaches the granted endpoint through the private grant seam that public `ConfigureMultipathIOV1` uses. The public peer rows use IPv4 loopback only.
- **Native BBR protected-member evidence.** No native observation relates protected storage reclamation to the native return ([B8](#concrete-blockers)). `TestE24SoftwareCiphertextBeforeNativeAndFinalFence` uses a controlled writer. X10–X12 observe BBR delivery, migration, close and lifecycle but record no protected-buffer lifetime fact.
- **Pressure.** X6 is a bounded observation and may legitimately be negative. It is not E2's induced traversal. UDP ENOBUFS has never been observed and stays an explicit residual unless X6 records it.
- **Relay.** The relay forwards payloads only, so ECN and IP metadata are not carried on topology rows. Its timing fidelity at load and its CPU cost are recorded, not assumed.
- **Lifecycle test address window ([#1568](https://github.com/GridCastIO/quicquic-go/issues/1568), closed).** The in-process `ordinarycost` lifecycle tests release a probe address before the server binds it. No step here runs `-tags ordinarycost` Go tests: X11–X13 run the drivers, whose role subprocesses bind driver-supplied addresses on the dedicated venue. Running those Go tests on a shared, busy host would meet #1568's reopen condition.
- **Metrics.** `ConnectionStats().PacketsLost` is unavailable for BBR. Darwin `ru_maxrss` is bytes. `go_heap_live` is live heap after a forced GC, not resident memory.
- **Scope.** All native results are example-level for this host, kernel, toolchains and candidate. They do not cover every kernel interleaving, general performance, fairness or other Darwin majors and architectures.
