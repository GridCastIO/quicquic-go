# Windows multipath implementation plan

**Date:** 2026-11-19. **Track:** MP-WIN in [MP-WIN-20261119](2026-11-19-windows-multipath-program.md). **Status:** Accepted handoff; implementation not dispatched. **Parent issue:** pending. **Normative scope:** Current outcome, boundaries, invariants, evidence, blockers and stop conditions. **Audit history:** [Handoff audit](../audits/2026-11-19-windows-multipath-handoff/README.md); [planning PR #1483](https://github.com/GridCastIO/quicquic-go/pull/1483).

## Outcome and settled profile

Deliver native Windows amd64 multipath through the existing endpoint and connection owners, followed by native qualification and one public activation PR. This replaces the broad W1–W6 work units in the [target/evidence plan](2026-11-19-windows-multipath-plan.md) with the child contracts below; completed [planning issue #1397](https://github.com/GridCastIO/quicquic-go/issues/1397) stays closed. The handoff publishes contracts and tracking only. It does not dispatch implementation, provision infrastructure or allocate a qualification campaign.

Preserve experimental default-off draft-21 QUIC v1, the common two-path cap, client initiation, same-ID migration, nonzero CIDs, path credit, backup defaults and PTO precedence. The target includes Reno primary/backup, experimental BBRv3 primary/backup and BBRv3 aggregate; Reno aggregate and enabled multipath with QUIC v2 remain refused. Ordinary peers remain ordinary, including granted ordinary QUIC v2. Aggregate requires explicit activation of each sending endpoint's intended paths; selecting aggregate alone does not activate backups. No general throughput or fairness guarantee is added.

The initial candidates remain Windows 11 Pro 25H2 build 26200.8037 and Windows Server 2025 Standard Evaluation 24H2 build 26100.32230, amd64, with Go 1.26.11 and 1.27.4. Those are historical candidate identities, not reserved or currently verified guests. Q1 must bind actual licensed disposable venues, servicing applicability and toolchain evidence before collection. Windows arm64/386 retain cross-build coverage but receive no runtime claim; other Windows release families, native granted USO, a higher path cap and full BBR qualification are separate outcomes. Linux amd64 support and unrelated platform programs remain intact.

The socket profile is an exact unconnected `*net.UDPConn`, granted before initialization. Preserve conflicts with wrappers, managed/external packet-I/O registrations, fixed-peer/network-policy modes, candidate groups, send-thread QoS and configured packet ceilings/jumbo. Explicit requests retain 1 ms–1 s duration, owned sockets 100 ms default, and the existing 20 ms endpoint tolerance and resource bounds. Write permission transfers writes/write deadlines only, with no read-deadline or caller-close authority. Transport detachment and transport-wide native join remain distinct. No custom IOCP implementation, timeout worker, second queue, runtime patch, hidden public test override or copied connection-policy state machine is allowed.

Native granted egress starts scalar. Ungranted Windows USO, managed leases and ordinary Windows receive behavior remain unchanged. Library-created sockets may use URO under the existing receive-format permission; a caller's write grant adds no such permission. Granted ECN is endpoint-wide, including ordinary peers after absent negotiation. The endpoint publishes only qualified ECN; the connection/recovery owner selects marks using the current target socket and retains per-path validation. A later native-USO optimization requires its own accepted contract if measured scalar cost is unacceptable.

## Common slice contract and finite evidence

For R1–R5 the runtime is shipped behavior and socket/grant/borrow/capability guards are required safety enforcement. Tests are verification aids; plans, receipts and mirrors are process/traceability metadata. E/P/C artifacts are maintained verification aids for the selected Windows profile: transport test/interop maintainers own them; their payoff is attributable native ownership, interoperability and cost evidence; retirement is equivalent replacement or removal of that profile while retaining historical receipts. This handoff accepts those finite readiness deliverables. It does not make every new aid a recurring required CI check: Q1 records the specific continuing-coverage payoff, domain, owner, retirement and authority before Q2 adds one. No recursive completeness requirement is imposed on an aid.

The runtime representation domain is exact unconnected sockets, typed endpoint requests/results and existing typed path/configuration state. Go's UDP/runtime layer and x/sys Windows ABI types own external native representation; existing QUIC parsers/AEAD own wire syntax. R3 reuses the bounded Windows CMSG decoder, not a general scanner. Ownership/capability invariants are universal within the declared socket/typed-state domain; tests and native measurements supply finite example-level evidence, not proof of all kernel schedules. Fixture input/output is a mechanically checked canonical subset of versioned JSON records and explicit socket tuples; standard parsers own syntax and each named fixture owns required IDs, statuses, units and identity checks. Missing, duplicate, wrong-identity or required-skipped records fail accounting. Receipts never authorize runtime behavior themselves.

No slice adds persisted product authority or a restart format. Socket/process recreation exercises constructor/cleanup behavior; it is not a database restart obligation. Maintain one owner for each transition; platform adapters translate facts and do not decide connection policy. R3's completed internal reader is an inert expansion until R5 selects it; it grants no permission and changes no default factory. R2's private endpoint is useful through its real interface while public/private transport installation still refuses. Existing ordinary construction remains synchronous until R5 selects the complete native route. These intermediate states have no duplicate active owner, generic mutation bypass or double-open lifetime. R5 is the blocking integration step, not permission to land partial lifecycle semantics.

Each child has one representative positive per named behavior and one negative per materially distinct failure/owner listed below. These semantic cases terminate development evidence; do not add statistical repetitions, broad cross-products or a new mutation product.
