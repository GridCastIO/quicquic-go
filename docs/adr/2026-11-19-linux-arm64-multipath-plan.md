# Linux ARM64 multipath implementation and qualification plan

This plan completes the planning deliverable for [Linux ARM64 multipath (#1395)](https://github.com/GridCastIO/quicquic-go/issues/1395). The maintainer approved full parity with the Linux amd64 profile in the [issue brief (#1395)](https://github.com/GridCastIO/quicquic-go/issues/1395#issuecomment-7000964233), then approved this documentation-only approach on 2026-11-19. Public multipath support remains Linux amd64; this plan authorizes neither runtime activation nor a qualification campaign or campaign budget. The broad future slices below are superseded for dispatch by the audited [implementation contracts](2026-11-19-linux-arm64-multipath-implementation-plan.md) and [program index](2026-11-19-linux-arm64-multipath-program.md); this target/evidence plan retains the settled profile and source assessment.

## Source and decision

Source inspection is pinned to `0fbad183f7c92eba8fa234cb9194d87029e4014d`, the default branch on 2026-11-19. The issue's original baseline is `48dc6634fef404404647b7e64024303a52a4fb4e`. The completed [multipath program (#646)](https://github.com/GridCastIO/quicquic-go/issues/646) and [BBR continuation (#1374)](https://github.com/GridCastIO/quicquic-go/issues/1374) are source material, not reopened programs or reusable campaign allowances. Preserve the [endpoint ownership contract](2026-10-24-multipath-endpoint-plan.md), [Reno contract](2026-10-24-multipath-reno-plan.md), [BBR contract](2026-10-24-multipath-bbr-plan.md), [packet-emission ownership](0004-packet-emission-ownership.md) and [maintained-code conventions](../agents/conventions.md).

Reuse the existing Linux native endpoint and connection-owned path implementation. Source inspection found no ARM64-specific backend gap. The known work is platform admission, test applicability, architecture/toolchain/container identities, native evidence and support publication. A source build or architecture-neutral algorithm is not evidence of native correctness, deadline behavior or performance. Newly observed production defects require a scoped fix at the existing owner; this plan does not pre-authorize an endpoint, scheduler or recovery redesign.

Build coverage means a binary compiles. Runtime support means the public API admits and implements a declared configuration. Qualification means the recorded native cases support a bounded claim for a particular source, toolchain, kernel and venue. These remain separate statements throughout implementation and publication.

## Public profile to qualify

| Surface | Required ARM64 behavior and preserved boundary |
| --- | --- |
| Selection and protocol | Experimental, opt-in draft-21 multipath over QUIC v1. Disabling stays the default. `ConfigureMultipathV1` selects configuration; constructors and server-selected configurations validate it before advertisement/attachment. Enabled configurations listing QUIC v2 remain refused; unnegotiated traffic stays ordinary. |
| Path count and operations | One or two active/validating paths, including path zero. Preserve opening, validation, same-ID migration, local-use/status changes, abandonment, snapshots and transport detachment, existing nonzero connection-ID requirements and resource limits. |
| Controller/policy | Reno primary/backup remains the default; experimental BBRv3 primary/backup and experimental BBRv3 aggregate are required. Preserve both setter orders, clones and server-selected configuration checks. Reno aggregate and unsupported controllers remain refused. |
| Aggregate activation | Existing uncoupled paced byte round-robin; additional validated paths start as local backups. Each sending endpoint explicitly activates paths with `SetLocalUseV1("active")`. Exclude backups while an active path is eligible and preserve PTO precedence. No general gain or fairness guarantee. |
| Socket grant | Exact unconnected `*net.UDPConn`, explicitly granted before initialization or granted by an existing library-owned-socket helper. Exclusive write and write-deadline authority does not transfer read deadlines or caller close ownership. Duplicate-descriptor writes and caller interference remain contract violations. |
| Deadline/resource contract | Preserve accepted request duration of 1 ms–1 s, the 100 ms owned-socket default, the 20 ms supported-environment tolerance and existing queue, byte, participant, completion and diagnostic bounds. Do not relax limits to obtain a passing run. |
| Unsupported combinations | Preserve rejection of connected/wrapped sockets, managed/external packet I/O, fixed-peer/network-admission modes, candidate groups, send-thread QoS and configured packet ceilings/jumbo on the native multipath route. |
| Address families | Qualify IPv4-only, IPv6-only and dual-stack sockets with mapped IPv4 and native IPv6 delivery, packet info and ECN. The existing independent peer's IPv4 examples do not supply the other socket-family evidence. |
| Lifecycle | `WaitTransportDetachedV1` observes one connection's independence from a transport; `WaitMultipathIOStoppedV1` returns transport-wide write authority only after close and actual native/deadline work joins. Neither wait substitutes for the other. |
| Ordinary traffic | Preserve default-off and unnegotiated ordinary QUIC, ordinary v1/v2 where admitted, HTTP/3 and granted ordinary traffic. A grant affects every connection and public/stateless write on that transport, so its ordinary costs need ARM64 evidence. |

The eventual admission change belongs to the existing capability decision shared by `Transport.ConfigureMultipathIOV1` and `Transport.admitMultipath`. Extend Linux's architecture predicate to the qualified ARM64 profile while preserving amd64 and the common controller/policy checks. Do not add a separate ARM64 controller predicate, runtime compiler-version parser, or new kernel allowlist solely for this port. Document the exact tested kernel/toolchains and assess the proposed admission domain before activation; evidence for this guest does not claim universal kernels, ARM CPUs or NICs. Coordinate with the separate [macOS plan (#1396)](2026-11-18-macos-multipath-plan.md) if its platform helper lands first, preserving one capability owner without making either public activation depend on the other. Shared tooling dependencies are explicit in the current implementation graph.

## Native semantic evidence map

Future ownership/lifecycle work has material buffer/authority consequences across independently reachable states. Its supported domain is typed endpoint requests, typed public configurations and the declared UDP/wire profile. Endpoint control owns admission/expiry, the writer owns current native borrowing, the connection owns protocol consequences, and existing configuration validators/wire parsers own representations. Native execution provides example-level evidence, not proof of every kernel failure or interleaving. The table maps the finite semantic distinctions; it is not a Cartesian product or a claim that coverage already passed.

| Semantic class | Expected result and enforcement owner | Evidence seam and current status |
| --- | --- | --- |
| Grant/deadline authority | One live grant per exact socket; write/deadline authority returns only after successful join; no read/close ownership transfer | `TestNativeIOGrantValidation`, `TestNativeIOStopAndJoin`, public owned/explicit socket tests, and caller write/deadline use after native join. Assertions exist; ARM64 qualification missing. |
| Expiry before dispatch | Endpoint control publishes an unsubmitted result and releases queued ownership without writing expired payload | `TestNativeEndpointQueuedExpiry`, `TestNativeEndpointExpiredClaimAndNextDeadline`, native expired-before-dispatch and successor progress. Needs native execution. |
| Local backpressure/current timeout | Writer reports bounded uncertainty; connection does not turn local timeout/EAGAIN/ENOBUFS into network loss or tuple failure | Existing completion/error tests plus syscall-injected EAGAIN traversing the actual ARM64 Go poller/deadline path and useful progress afterward. Separate injection from real pressure observation. |
| Independent queued expiry | Control expires queued work while the current writer still borrows its storage | Existing deterministic endpoint tests and native queued-expiry class with current-write/poller witness. Needs ARM64 traversal evidence. |
| Segmentation/retry | Writer shares one absolute request deadline; accepted prefix is not replayed and uncertain/unsubmitted suffixes remain distinct | Existing software segmentation/prefix/request-error tests, actual Linux software grouping and yield witnesses, capability-observed GSO success/fallback and scalar retry. Simulated GSO EIO remains explicitly simulated. |
| Buffer lifetime and shutdown | Native return/deadline reset precede reclaim; sealing stops producers; join waits for native and producer work | Member-return/reset, overdue-borrow, software protection, `TestNativeLiveCloseDuringCurrentWrite`, `TestNativeSealStopsCapturedProducers`; focused race and real active-close/post-join writes. Native evidence missing. |
| Shared endpoint contention | Current participant/path/control/public/stateless bounds and service rules hold; diagnostics cannot block the writer | Current admission/service-turn tests and request-contention native class with progress/refusal/occupancy records. Reuse current expectations, not historical fairness assumptions. |
| Validation/migration/stale feedback | Path owner validates before cutover, retains same-ID continuity and fences old-tuple feedback | Admission/migration tests, public `TestMultipathMigrateAndDetach`, independent migration/rebinding and abandon/reopen cases. Native public run missing. |
| Connection-specific detachment | Detachment owner prevents old transport actions for the departing connection while a survivor can still use that transport | Existing detachment/shared-transport tests plus native survivor transfer before closing the old transport. Transport-wide join is a separate assertion. |
| Metadata/ABI/families | Existing socket owners preserve intended source/interface, destination, ECN and datagram boundaries | Native IPv4/IPv6/dual-stack scalar and available grouped paths, cmsg layout/round-trip controls and peer observations. Big-endian/32-bit targets are outside this profile. |
| BBR feedback and policies | Existing recovery/scheduler owners preserve sample provenance, local credit, protected buffers, migration/ECN fences and eligibility | `multipath_bbr_test.go`, `bbr_native_credit_test.go`, `bbr_native_large_test.go`, public BBR/aggregate transfer and constructor tests. Reno-only observations cannot replace BBR evidence. |
| Both-active aggregate traffic | Scheduler preserves backups/PTO rules and produces useful traffic on both explicitly active paths | Existing STREAM witness plus fresh sender deltas and receiver ingress-path DATAGRAM witnesses after activation, in both peer roles. Native measurements remain separate. |
| Independent wire behavior | Existing protocol implementations interoperate through public APIs | Eight existing Reno scenarios in each role; useful-transfer, abandon/reopen/late-feedback and same-ID migration/rebinding in each role for each BBR policy. Ordinary peer controls establish adapter readiness; zero vectors/controlled peer remain separate from independent coverage. |
| Ordinary preservation/cost | Default-off traffic remains unchanged; granted ordinary traffic preserves useful delivery, bounded storage and close/join | Ordinary v1/v2, HTTP/3 and fallback regressions; native controller-matched cost comparisons. ARM64 costs and exceptions are unknown. |

Use three seams with independent expectations. Deterministic adapters expose ownership/disposal/interleaving errors but miss OS behavior. Real `*net.UDPConn` tests expose deadlines, metadata and joins but do not establish independent interoperability. Public constructors plus the pinned peer expose integration/wire errors but miss unexercised kernel failures and general performance. Do not copy production platform predicates into expected acceptance. Future focused changes use TDD at those seams where applicable; this documentation PR needs no Go test or TDD cycle.

## Native method, ordinary costs and aggregation

Before public admission, endpoint fixtures may use existing private `configureNativeIO`/`startNativeEndpoint` seams. Public qualification must use the real gate on the unmerged activation candidate. Do not add production hooks, exported qualification bypasses, fake OS identity, environment admission overrides or a second deadline owner.

Adapt the existing Linux native method under E1 after A0 establishes its preparation inputs; Q1 binds execution and Q2 establishes actual traversal feasibility: real UDP sockets, syscall-level EAGAIN injection, observed `sendmsg` results, a stack through the installed Go poller/write path, and deadline return. Pin the installed toolchain's poller source and ARM64 syscall path. The retry case uses disposable namespace/nftables behavior; the GSO EIO trigger may remain explicitly simulated if no native trigger exists. Preserve the six semantic classes and current software-group/yield witnesses. Missing traversal, required skips or unsuitable tracing privileges stop qualification; do not substitute a fake passing call or cross-compilation.

Injection proves traversal, not real congestion. Run the bounded actual-pressure observation separately and record whether waiting occurred, socket-buffer values and relevant counters. E6 observed no real pressure wait and used simulated GSO EIO; preserve those historical limits. Compare the 20 ms tolerance only with uninstrumented timings under the supported scheduler assumptions, not ptrace timings. Software segmentation must work without hardware offload. For conditional receive-coalescing/GRO evidence, use a transport-created multipath socket: a caller-supplied socket's write grant does not grant receive-format permission, and native multipath excludes external packet-I/O registration. Preserve that distinction when recording capability. Qualify available GSO/GRO paths only with observed capability, engagement and delivered datagrams; absent virtual-NIC offload is not a failed hardware claim to rescue with retries. A hardware-specific performance claim needs a separately scoped native NIC venue.

Compare granted ordinary traffic against an unregistered, controller-matched baseline on the same source/binary and venue. Include STREAM, DATAGRAM, mixed bulk, stateless/public response pressure, idle/backup/retired-path memory and active close/join. Report useful application bytes/goodput, process CPU per useful byte, RSS, relevant call latency, offered/received stateless traffic and local disposal/loss. Preserve the existing [ordinary-cost criteria](2026-10-24-multipath-reno-plan.md#r18--measure-ordinary-peer-costs-on-granted-endpoints), including the 1.10 CPU ratio and 10% RSS-growth limits where applicable. Q1 must bind the shared workloads and ARM C1 accounting before collection. Existing amd64 exceptions remain exact historical decisions; they do not create ARM64 tolerances.

BBRv3 primary/backup needs its own ordinary-cost disposition, native protected-buffer/credit evidence and existing public peer scenarios. The full-controller qualification program remains separate and is not a new prerequisite. Experimental status remains explicit even when scoped multipath qualification succeeds.

For aggregation, the selected shared owners provide the successor to the retired comparison fixture using the [B11 comparison source (#1384)](https://github.com/GridCastIO/quicquic-go/tree/8c34fbac874adf55f096b6c67d51244160169422/interop/multipath) and the [B11 contract](2026-10-24-multipath-bbr-plan.md#b11) as reference. Verify the actual merged shared successor against the current contract; the frozen revision remains reference material, not an executable dependency to revive. Compare ordinary BBR path A, ordinary BBR path B, two independent BBR connections and the current two-path aggregate under balanced disjoint, unequal delay/rate and shared-bottleneck conditions, preserving useful-byte and ordinary-competitor semantics. Retain the existing applicable benefit/cost criteria; no new gain claim, threshold, sample count, statistical claim or campaign allocation is made here. Exact workload applicability, finite operational inventory and acceptance of any ARM64-specific cost exception require a concrete protocol before collection. An invalid or negative result leaves activation unmerged pending owner disposition; it does not silently reduce the required parity profile.

## Design costs, artifacts and stop conditions

| Choice | Consequence and rejected alternative |
| --- | --- |
| Reuse the existing Linux endpoint and one admission owner | Adds platform applicability/evidence obligations, with no new goroutine, state mirror, queue or protocol owner. A separate ARM64 backend duplicates lifetime and failure contracts without a demonstrated gap; rejected on merit. Revisit only if native evidence identifies a platform-specific requirement that cannot fit the existing owner. |
| Parameterize maintained Linux fixtures and exact architecture identities | Adds supported input cases to existing verification owners rather than a second framework. Keep amd64 defaults and explicit architecture/toolchain validation. An unchecked architecture wildcard weakens identity attribution; rejected on merit. |
| Use native hardware virtualization initially | Exercises the ARM64 Linux kernel/runtime with an available venue; virtual NIC and guest CPU accounting limit performance claims. Emulation cannot substitute. Physical ARM hardware/NIC measurements are deferred until a claim or observed defect requires them and a venue is provided. |
| Keep support unchanged until the full activation candidate passes | Adds no temporary public capability or rollback obligation. A production test bypass or early Reno-only activation adds authority/profile obligations and violates the approved parity outcome; revisit a reduced profile only on explicit owner decision. |
| Scope a successor measurement fixture | Adds a finite verification aid with declared ownership/retirement, preserving historical bytes and claims. Silently treating a retired collector as a maintained dependency is rejected; archived code is source material, not a current executable contract. |

The present ADR and usage pointer are process/traceability metadata. Their guarantee is source-backed, example-level assessment over the finite issue requirements and observed venue. Runtime contract closure is not triggered by this documentation-only change. Future admission is shipped behavior and required refusal enforcement; tests/drivers/CI are verification aids, and receipts remain metadata. Future maintained aids require explicit scope approval: transport tests/integration own them, their payoff is repeatable native regression and identity/skip detection, their domain is the named platform/toolchain/scenario profile, and retirement requires equivalent replacement or feature removal. ARM-specific finite entrypoints retire after the definitive ARM support decision with raw evidence archived; shared tools retain their own maintenance/retirement contracts. This plan does not recursively turn harness completeness into a runtime guarantee.

The full effects of other ARM CPU/NIC configurations, untested kernels, shared-host timing and native offload engagement are unverified. Reassess affected evidence rather than asserting portability from build tags. No new public API, wire schema, dependency, scheduling policy, resource limit or security surface is approved. A necessary change to those boundaries, failed native traversal method, unsupported required address family, negative required evidence or inability to deliver parity is a stop for a concrete maintainer decision before further implementation/qualification. Failed or missing evidence is not success and does not authorize repeat-until-pass collection.
