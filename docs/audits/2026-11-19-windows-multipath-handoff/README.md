The first full-panel review of [PR #1502](https://github.com/GridCastIO/quicquic-go/pull/1502) exposed concrete contract omissions. For P2, pinned picoquic’s direct [`qlog_fns.c`](https://github.com/private-octopus/picoquic/blob/fbd46d9a1f54ebf9397f2ee6355b5019ab379fb7/loglib/qlog_fns.c#L265) records the actual multipath `unique_path_id` on packet events; [`qlog_frames.c`](https://github.com/private-octopus/picoquic/blob/fbd46d9a1f54ebf9397f2ee6355b5019ab379fb7/loglib/qlog_frames.c#L108) emits STREAM ID, offset and length. `picoquic_set_qlog` registers this direct producer from the existing `picoquic-log` CMake target; P2 includes that target in the peer’s current `picoquic-core` link declaration. The initially inspected binary-log converter exposes similar fields but is not the chosen collection interface. Its [qlog instructions](https://github.com/private-octopus/picoquic/blob/fbd46d9a1f54ebf9397f2ee6355b5019ab379fb7/doc/QLOG.md) require full logging to avoid the default packet limit and orderly finalization for complete JSON. The repository already exposes typed Go `PacketReceived` path/frame observations. Those existing producers support a bounded actual-ingress adapter without attributing reassembled callback bytes to the wrong packet or adding a wire parser. The new P2 owns that adapter and active-phase matching; shared [DATAGRAM witness #1489](https://github.com/GridCastIO/quicquic-go/issues/1489) remains the phase-interface predecessor.
