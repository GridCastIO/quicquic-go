# E04 observer source notes (#1368)

This disposable observer is based on `ba84302dcc56d65712ba1e604b8fc50509367b25`, whose asynchronous runtime equals E02. It implements the committed E04 plan; no observer code belongs in the final product change. Run only the planned stateless-pressure diagnostic pair. Instrumented timing is descriptive and cannot qualify performance.

The fixture adds `bbr_observation` to both server connection results and client flow results. The connection writes a fixed array of 128 cumulative snapshots at the existing send-opportunity tracing point, with no qlogger. Only the first `snapshot_count` entries are valid; trailing zero entries have no meaning. `snapshot_overflow` records omitted eligible observations. The cadence is at most once per second; an inactive connection produces gaps rather than a synthetic sample. `mono_ns` is process-local monotonic time. `unix_ns` is derived from that existing timestamp through `monotime.ToTime`, without reading another clock. Correlate snapshots with the fixture timeline and report adjacent snapshot deltas; they are not exact measurement-window counters.

`final_before_teardown` captures the connection's last state before local drain and controller/sampler disposal. `final_recorded` establishes that this freeze occurred. The ordinary fixture reads observer pointers only after connection `Context().Done()`: server extraction also follows listener/transport closure and worker completion, and client extraction follows `CloseWithError`. No live controller state is read by the fixture goroutine. Final totals include startup and warmup, and omit teardown work after the freeze.

Recovery counters count actual ACK feedback events after sampler qualification. Empty local completion events, including E02's explicit empty diagnostic sample, do not increment valid or invalid sample counts. `delivered_bytes` counts new logical delivery in those ACK events; `sample_rate_sum/min/max` aggregate valid sample rates, not byte-weighted throughput. Excluded and timing-generation-mismatched packet/byte counts overlap and must not be added. Delivery-registration counters include ACK-eliciting, non-path-probe registrations. First-local-ACK and early-ACK counters count each local registration once across both live history and retained ECN receipts; they include handshake/control registrations. Timing-fence totals accumulate across sampler replacement, and sampler reset counts expose lifecycle boundaries. Snapshots also expose live generation and qualification ordinals; a difference between the ordinals is a position gap, not a duration or necessarily a number of pending packets.

Controller counters distinguish feedback reaching the model from usable delivery samples. `clock_rejected` includes zero or backward event timestamps; `ack_clock_rejected` restricts this to ACK feedback. `model_usable_samples` increments only after the model's clock, round-evidence and sample-validity checks. Controller and recovery counters survive resets. Model bandwidth, pacing and delivery rates are bytes per second; `effective_pacing_rate` includes emission's existing one-percent margin. Controller minimum RTT and recovery minimum/smoothed RTT remain separate facts.

`early_ack_with_participant_hint` is advisory. The atomic participant hint can signal a terminal result, readiness, fault, revocation or retirement. The writer's raw return publication can precede endpoint reconciliation and this hint. A positive value does not identify the ACK's exact packet result; a zero value does not prove that native I/O has not returned. `early_ack_with_deferred_facts` independently reports a nonempty connection-owned deferred-result list. Observation neither consumes hints nor acquires endpoint control.

Emission's `OrdinaryAttempts/Successes/Refusals` observe the existing reservation predicate under the existing credit lock. `RefusedUsablePartialRoom` requires at least one packet of free credit, a requested reservation larger than that free credit, no isolated reservation and no old-generation pending bytes. It establishes only that a smaller credit reservation could fit; it does not establish that a complete alternative send is legal. `RetryNanoseconds` spans first ordinary refusal to next ordinary success using existing opportunity timestamps, including intervening protocol and pacing work. `RetryOpen` identifies an unfinished interval. Queue-capacity checks and refusals count calls, potentially several per opportunity. `EndpointCapacityRefusals` means native sender `WouldBlock`, including registration and local-sidecar limits; it does not prove endpoint mailbox exhaustion. `DefaultStopWithProgress` separates successful handoffs from the zero-valued `NoData` stop. Handoff totals include BBR control/probe traffic as well as ordinary data.

Native `OpportunityToReturn` begins at the existing BBR reservation/opportunity timestamp, also used for the ordinary batch's packet registration, and ends at the member's native-return timestamp. `ReturnToConsume` ends at one monotonic clock read at the start of consuming that result, before per-member recovery work. It includes endpoint reconciliation and connection scheduling. `ConsumeClockReads` records this observer overhead. Histograms use inclusive upper bounds of 10, 25, 50, 100, 250, 500 and 1000 microseconds, followed by infinity. Missing or backward timestamps are counted separately and excluded from duration totals and buckets. `AcceptedBytes` includes only fully accepted members; `AcceptedDatagrams` also includes a partial accepted prefix without guessing its byte count. No packet receives an additional clock read, allocation, formatting or I/O operation.
