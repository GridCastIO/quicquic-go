## Actual selection and representation change

The [larger-member predicate](https://github.com/the-sarge/quic-go-fast/blob/86b9a1bdf2c34cb846140f11115d62557de5a531/packet_emission_gso.go#L18-L31) requires a BBR policy, a local sender that is also the queue, no multipath registry, no selected route and a current packet size M no greater than `protocol.MaxPacketBufferSize` (1,452 bytes). The production local-sender installation remains `useNativeOrdinary`. The ordinary BBR call chain additionally requires confirmed handshake and the existing GSO capability decision before the larger plan/allocation is used. Reno, unregistered BBR, negotiated multipath, routed work, unconfirmed coalesced work, exempt control/probes and GSO-disabled construction retain their previous selection.

**The size test is current M, not the configured maximum.** A jumbo-configured connection whose current M is still at or below 1,452 is eligible. Once it is actively using jumbo packets, M exceeds 1,452 and this new selection is excluded. This is a narrow ordinary native BBR exception to [F10's historical statement (#1224)](../../adr/2026-11-05-jumbo-packets-plan.md#f10) that a configured connection still sending standard packets keeps the prior batch size; that old standard-size preservation statement cannot be carried across E06's selected domain. The existing Linux active-jumbo storage/send-limit behavior remains, including its synchronous protection fallback. Do not describe E06 as excluding every jumbo-configured connection or preserving every jumbo-configured batch.

The [planner and allocator](https://github.com/the-sarge/quic-go-fast/blob/86b9a1bdf2c34cb846140f11115d62557de5a531/packet_emission_bbr.go#L335-L361) use the same predicate. The planner caps the opportunity by existing pacing/window allowance and a 65,507-byte UDP payload limit, rounded to whole maximum-sized packets. The allocator selects the existing 65,535-byte pool only when GSO is available and the bounded request exceeds the old 20 KiB tier. Smaller requests keep their prior pool. The existing 64-segment limit remains. At M = 1,452, a full ordinary batch can therefore contain 45 packets / 65,340 bytes instead of 14 / 20,328; actual supply, allowance and ECN can end it earlier. At M = 1,200, the payload ceiling permits 54 full packets / 64,800 bytes. These are geometry bounds, not measured average batch sizes.

The [shared protection-plan constructor and validator](https://github.com/the-sarge/quic-go-fast/blob/86b9a1bdf2c34cb846140f11115d62557de5a531/native_protection_plan.go) now admit a 65,535-byte buffer with the existing large plan's `maxGSOSegments + 3` inline recipe storage. This is a real extension of the admitted protected representation. The existing 1,452-byte and 20 KiB cases retain their behavior; the recipe layout, `uint16` bounds checks, exact-buffer binding, freeze, transform, pool and release owners are unchanged. The endpoint's existing `checkedSize` owner reaches the extended `validForMember` validation for the new protected member; this record does not claim that the whole admission domain is unchanged.

The [construction guard](https://github.com/the-sarge/quic-go-fast/blob/86b9a1bdf2c34cb846140f11115d62557de5a531/native_protection_construction.go#L108-L120) prevents the shared constructor extension from silently changing every 65,535-byte buffer's placement. Before obtaining a plan for that tier, it requires an active BBR opportunity, a paced ordinary reservation larger than 20 KiB, the larger-member predicate and the current bounded-GSO decision. Failure uses the existing synchronous path. The prior construction ticket still validates sender, record, identity, packet prefix and route ownership. Reno and active jumbo therefore do not acquire deferred protection merely because their buffer uses the coalesced tier.

## Preserved owners and changed costs

Against E02, `native_endpoint.go`, `native_ordinary.go`, `native_staging.go`, `native_transport.go`, `native_response.go`, `local_send_credit.go`, `bbr_send_policy.go`, the native qualification fixture and its driver are byte-identical. The one-handoff opportunity and outer `finish` are restored to E02 semantics. There is no new owner, queue, cross-call builder, native syscall API, deadline source, retry policy, completion timestamp, credit-return boundary or shutdown mechanism. Q pacing, 2Q pending-byte credit, the first absolute request deadline and existing owned-buffer/backing limits remain the controlling mechanisms.

The larger protected member changes work at those owners: more encryption can occur before the first native submission, one GSO request can carry more packets, larger reservations can refuse when the old request fitted, and buffer backing rises when the new tier is selected. Connection receive/timer servicing still resumes after the one bounded handoff, but that handoff can take longer. Those costs are not erased by unchanged owner source. Focused larger-member tests must establish construction/protection/decryption, offset and segment bounds, admission binding, Q/2Q, original deadline, GSO acceptance and EIO fallback, partial outcomes, revocation/expiry and exact-once disposal through the real owners. They must also cover the excluded-route selections and tier reuse. The existing [N11 protection contract (#1240)](../../adr/2026-11-04-native-endpoint-efficiency-plan.md#n11) supplies these lifetime and failure obligations, including focused race and affected build-tag coverage; it does not require a new harness or operational matrix.
