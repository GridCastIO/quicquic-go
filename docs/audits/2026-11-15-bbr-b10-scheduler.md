## Runtime and source applicability

The base is `ecdd46d027077d11837271cecf7339a44044b087`. The existing connection-owned scheduler now always applies paced byte-round-robin: pending PTO first; ordinary work held without a primary; active paths exclude backups while eligible; ready paths precede unready paths; sendable-now precedes future-paced, then earlier future send time, fewer scheduled bytes, and lower wire ID. Registry ordering supplies the stable wire-ID tie. Byte charging and rebasing are unchanged. Delivery-rate, queued-byte and RTT fields and reads used solely by arrival ranking are removed; BBR's sampler, controller and pacing remain intact.

The sole new seam is an unexported `multipathSelection.experimentScheduler`, copied by value with Config and captured during registry activation. Public configuration writes only its zero primary/backup value. In-package experiments select it before constructors run; platform, version, controller and exact socket-grant admission still apply. There is no running-connection policy setter, second lifecycle, new timer or worker. B12 removes the selector.

Production differences are confined to `multipath_scheduler.go`, the aggregate-only view fields/reads in `packet_emission_path.go`, the private config field in `multipath_api.go`, and its activation assignment in `multipath_credit.go`. Primary/backup continues through the unchanged `selectPath`; ordinary connections never activate this registry. Removed aggregate model reads were observations without mutation. The BBR opportunity planner, emission construction/registration/handoff, native ownership/completion, recovery/sampling, migration/ECN, and ACK-turn PING owners are unchanged. Therefore the [B9 source-applicability record](2026-11-15-bbr-b9-support.md#candidate-specific-applicability) and its linked ordinary/native/Reno evidence carry with their original limitations and exact accepted cost exceptions. No new performance observation or broader native guarantee is claimed.

## Finite evidence

The first unequal valid rate/RTT regression failed the old estimator (expected path zero's byte turn, selected path one) and passed when selection switched to paced byte order. After removing the obsolete fields, `TestAggregateBBRBeforeAndAfterSamples` retains the behavioral witness at the real-packer seam: both controllers obtain valid samples, path zero acquires a slower RTT, and its less-served turn still emits STREAM bytes on path zero alone. The config activation regression separately failed when the requested aggregate choice remained primary/backup, then passed after the one-time activation assignment.

The focused selection cases cover byte order, pacing, stable ties, no primary, PTO precedence, backups, no ready candidate and DATAGRAM fit/steering. `TestAggregateByteLedger` covers actual byte charges, rebasing and returning members without debt; the existing migration and retirement tests additionally assert same-ID ledger retention and fresh replacement state. Existing real-packer tests retain local-credit, GSO, isolated-MTU, native-capacity and non-destructive extraction evidence. Public selection still rejects aggregate, while copy/activation tests cover zero state and independent config values. These are finite examples inside registry-validated ordered views of at most two live paths, with unchanged eligibility and ownership guards.

`TestMultipathAggregateTransferAndJoin` executes on native Linux amd64 through public BBR admission, with both connections selecting aggregate before activation. Both client paths stay active. The test verifies exact received STREAM bytes and all 32 DATAGRAM payloads, observes actual sent STREAM and DATAGRAM frames on both wire paths through the existing qlog sink, then closes both connections and joins all granted endpoints. The initial native run recorded STREAM bytes `{0:75384, 1:18824}` and DATAGRAM counts `{0:20, 1:12}`. Those are carriage witnesses, not rate, fairness or packet-count targets. The native venue is Minimax, kernel `7.0.0-30-generic`, Go 1.27.4, with `GOMAXPROCS=4`; the ordinary and focused race suites remain the existing deterministic validation, not additional peer campaign instances.
